# SEED B3 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans with the owner's native workflow. Progress/evidence live in the canonical B3 execution log.

**Goal:** Evaluate the exact prospective prediction after its target observation, recording errors without behavioral influence.

**Architecture:** A pure `evaluate_prediction(prediction, actual_state) -> PredictionEvaluation` calculates four per-signal evaluations and coverage-aware aggregation. The cycle calls it once after outcome derivation and before legacy reward; the existing atomic write stores the same evaluation dictionary. Schema stays v2.

**Spec:** Owner's approved “SEED 0.2 — Batch B3: Prediction Error” instruction. **Tech stack:** existing standard-library Python/SQLite and pytest.

## Constraints

Branch `seed-0.2-b3` from verified `008b704`; no merge, installed-memory access, deployment, B4+, sensor/predictor/policy rewrite, or calibration. B2 confidence remains evidence support. Use generic telemetry plus tests/artifact for inspection; no optional rolling API or UI work.

## Contract and review focus

- Targets: battery_pct, disk_free_pct, load_ratio, network_reachable (actual key network). Numeric validation matches target domains: finite nonboolean numbers, percentages 0..100, load >=0.
- Signed error actual−predicted; absolute error its magnitude. Percentage normalization abs/100; load abs/max(1,abs(predicted),abs(actual)), all normalized values bounded to 0..1.
- Boolean classification plus Brier when an actual finite probability in 0..1 exists; otherwise mismatch. Invalid probabilities are omitted, never echoed.
- Not-evaluated reasons distinguish unavailable prediction, invalid prediction, and unavailable actual. No fabricated scores for missing data; zero evaluable signals yields unavailable aggregate with null scores.
- Explicit evaluator/version and prediction model/version/horizon. Validate supported B2 metadata; reject unsupported/malformed payloads safely rather than reinterpret them. Accept plain dicts and bounded serialized JSON for direct evaluation; core uses dicts. At most four target lookups, no history reads. Oversized/deep malformed serialized input is rejected safely.
- Mean available normalized errors; accuracy_score=1−mean is an engineering summary, not calibrated probability. Coverage=n/4 remains separate.
