## Design and interfaces

- Pure curiosity_v1 assessment: B3 error×coverage anchored score, uncertainty and
  novelty from B4-valid samples and the most specific published prior belief.
  Canonical B4 sample/contradiction helpers are shared without semantic changes.
- One bounded keyed read snapshots at most eight published scope candidates;
  select action then global per signal. Persist four bounded component records
  so later belief revisions cannot change the meaning of the assessment.
- Additive v4 tables: curiosity_assessments keyed by transition; curiosity_runtime
  singleton last claim transition/time. Experience+queue+exact assessment atomic.
- Attention separate from score: HIGH/VERY_HIGH, coverage>=.5, no selected reflect,
  resource guards, owner stop, >=10 completed autonomous transitions AND >=300s.
  Count actual transition rows using an indexed LIMIT10 range, never ID subtraction.
- Claim with BEGIN IMMEDIATE; update claim+cooldown+event before reflect. Never retry
  claimed work, including crashes/failures. No automatic attention replay on startup.
  Suppressed decisions are terminal for that transition. Both success and failure
  consume the cooldown; serious SQLite errors propagate, ordinary auxiliary errors
  are recorded and do not abort the already completed transition.
- Existing reflect gains explicit provenance, with no algorithm change. Only one
  additional existing reflection; no perception, delay/policy change or fake transition.
- Read-only recent assessments and rolling summaries bounded to latest100.
